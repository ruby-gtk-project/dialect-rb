# Translation parity — dialect-rb vs upstream `origin/main`

## msgid count

`po/` is a checked-out git submodule (`dialect-app/po`). `po/ui/dialect.pot`:

    grep -c '^msgid' po/ui/dialect.pot
    123

Upstream also ships a second catalog (`dialect-cldr-langs`, generated by
`po/gen_cldr_langs.py` for language-name strings) and separately calls
`_()` directly at roughly 35 call sites in `dialect/window.py` alone.

## Survival: zero, unchanged across this round's three commits

Re-checked at `fc10569`, after `c3fcdf9`/`bc3e087`/`fc10569` (the
text-to-speech wiring round):

    grep -rn "gettext\|bindtextdomain\|FastGettext\|_(\"" lib exe
    → lib/define.rb:30 and lib/languages.rb:23-26, comments *about* gettext
      (describing what upstream does), not calls to it. No other matches.

There is no `bindtextdomain`, no `_()` call, no `pgettext`, no gettext gem in
the `Gemfile`, and no `GetText`/`FastGettext` require anywhere in `lib/` or
`exe/`. The new strings this round added — "Listen to source text", "Listen
to translation" in `lib/shortcuts_window.rb`'s Text-to-Speech group — are
themselves bare English literals too, the same as every other string in the
file; the newly-ported component did not introduce a new translation path,
and it did not need to, because none existed to join. Survival rate: **0 of
123** msgids in `dialect.pot`, plus 0 of the CLDR-language catalog's strings.

## This remains accurately disclosed

`component-identification.md` and `component-parity.md` both state this
plainly again this round. The drive suite's own step 48
("the translation catalogs are checked out") only asserts that `po/` and
`po/cldr-langs/` exist as directories on disk — it does not claim, and its
name does not imply, that any string inside them is reachable at runtime.
Read literally it is accurate; a reader who stops at the step's title rather
than its body could still walk away thinking more is covered than is, which
is worth naming here even though the title itself does not overclaim.

## What's missing, concretely (unchanged from last round)

1. A gettext binding (`gettext` gem, or `FastGettext`) in the `Gemfile`.
2. `bindtextdomain`/locale setup at startup in `lib/main.rb`, naming the
   `dialect` domain and the checked-out `po/` catalogs' install path.
3. Every user-facing string literal in `lib/*.rb` — window titles, button
   labels, menu items, error messages, the shortcuts dialog (now including
   the Text-to-Speech group's two new strings, same gap as every other row
   in that file), the preferences dialog, the About dialog — wrapped in
   `_()`/`pgettext()` equivalents.
4. A way to generate/update a Ruby-side `.pot` (or reuse the checked-out
   `po/ui/dialect.pot` if msgids are kept string-identical) so the existing
   translator community's work in `po/` actually applies.
5. The CLDR language-name catalog (`dialect-cldr-langs` domain,
   `po/gen_cldr_langs.py`) wired into `lib/languages.rb`, which still only
   has a comment noting upstream "additionally runs the name through
   gettext's pgettext" — the comment documents the gap without closing it.

## Verdict

**Not clean.** 0 of 123 msgids are reachable at runtime, unchanged across
this round's three commits. This is the single largest remaining unit of
work in the port, and it is the only one of this audit's five reports with
nothing to report as improved this round.
