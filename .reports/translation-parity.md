# Translation parity — dialect-rb vs upstream `origin/main`

## msgid count

`po/` is a checked-out git submodule (`dialect-app/po`). `po/ui/dialect.pot`
contains:

    grep -c '^msgid' po/ui/dialect.pot
    123

Upstream also ships a second catalog (`dialect-cldr-langs`, generated by
`po/gen_cldr_langs.py` for language-name strings) and ~35 call sites in
`dialect/window.py` alone wrapped in `_()`.

## Survival: zero, unchanged since the last round

Re-checked this round, after the most recent commits (`c3fcdf9`, `090b470`,
`54b3308`):

    grep -rn "gettext\|bindtextdomain\|FastGettext\|_(\"" lib exe
    → lib/define.rb:30 and lib/languages.rb:23, both comments *about* gettext,
      not calls to it. No other matches.

There is no `bindtextdomain`, no `_()`, no `pgettext`, no gettext gem in the
`Gemfile`, and no `GetText`/`FastGettext` require anywhere in `lib/` or
`exe/`. The new `lib/speech_button.rb` wiring in `c3fcdf9` does not touch
this at all — no new string went through any translation path, because
there still isn't one. Every one of the 123 msgids in `po/ui/dialect.pot`,
and every string in the CLDR language catalog, is unreachable at runtime.
Survival rate: **0 of 123**.

## This is accurately disclosed, not hidden — and that still matters for scope, not severity

`.reports/component-inventory.md` and `component-identification.md`/
`component-parity.md` all say this plainly this round too. That is the right
way to report a gap — naming it instead of letting "po/ is checked out" imply
more than it does. It does not change the scope of what's missing: a user
with `LANG=de_DE` (or any of the ~100+ locales `po/ui/LINGUAS` lists) still
gets the identical English-only UI as a user with no translations installed
at all. Total, not partial, translation gap.

## What's missing, concretely (unchanged)

1. A gettext binding (`gettext` gem, or `FastGettext`) in the `Gemfile`.
2. `bindtextdomain`/locale setup at startup in `lib/main.rb`, naming the
   `dialect` domain and the checked-out `po/` catalogs' install path.
3. Every user-facing string literal in `lib/*.rb` — window titles, button
   labels, menu items, error messages, the shortcuts dialog (including the
   still-missing Text-to-Speech group's own two strings — see
   `component-parity.md`), the preferences dialog, the About dialog —
   wrapped in `_()`/`pgettext()` equivalents.
4. A way to generate/update a Ruby-side `.pot` (or reuse the checked-out
   `po/ui/dialect.pot` if msgids are kept string-identical) so the existing
   translator community's work in `po/` actually applies.
5. The CLDR language-name catalog (`dialect-cldr-langs` domain,
   `po/gen_cldr_langs.py`) wired into `lib/languages.rb`, which currently
   only has a comment noting upstream "additionally runs the name through
   gettext's pgettext" — the comment documents the gap without closing it.

## Verdict

**Not clean.** 0 of 123 msgids are reachable at runtime, unchanged across
this round's commits. This remains the single largest unit of work left in
the port and should not be understated by `po/` itself being present in the
tree.
